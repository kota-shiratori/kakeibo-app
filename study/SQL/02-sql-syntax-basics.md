# SQL の書き方の基本ルール（クォート・大文字小文字・セミコロン・コメント）

## 概要

SQL 文そのものの意味に入る前に、**文字列の囲み方** や **文の終わり方** など、書き方の基本ルールを押さえておきます。学習メモで出たエラーのいくつかは、このルールを知っていれば防げるものでした。

## このプロジェクトでの実装

学習メモの次の 1 行は、そのまま実行するとエラーになります。

```sql
UPDATE transactions SET amount = 50000, date = ''2025-10-02 WHERE id = 1;
```

実験で確認した結果:

```text
ERROR:  syntax error at or near "2025"
LINE 1: UPDATE transactions SET amount = 50000, date = ''2025-10-02 ...
                                                         ^
```

`''` が「空文字列」として閉じてしまい、その直後の `2025-10-02` が文法上ありえない位置に来たためです。正しくは次のとおりです（→ 08 章）。

```sql
UPDATE transactions SET amount = 50000, date = '2025-10-02' WHERE id = 1;
```

## 重要語句

- **文字列リテラル**: SQL の中に直接書いた文字列の値。**シングルクォート `'...'`** で囲む。
- **識別子**: テーブル名・列名など「名前」。必要なときだけ **ダブルクォート `"..."`** で囲む。
- **キーワード**: `SELECT` / `WHERE` など SQL の予約された語。
- **セミコロン `;`**: 文の終わり。

## 仕様・注意点

### シングルクォートとダブルクォートは意味が違う

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `'x'` | 文字列 `x` という **値** | `WHERE item = 'カフェ'` |
| `"x"` | `x` という名前の **列やテーブル** | `SELECT "item" FROM "transactions"` |

JavaScript の感覚で `"x"` と書くと、値ではなく列名として扱われます。実験で確認した結果:

```sql
INSERT INTO transactions (item, amount, date) VALUES ("x", 1, '2025-10-01');
```

```text
ERROR:  column "x" does not exist
```

- 文字列の中にシングルクォート自体を入れたいときは `''` と 2 つ重ねます（`'It''s'` → `It's`）。上の `''2025-10-02` のエラーは、この「空文字列 `''`」として解釈された結果です。
- アプリから値を渡すときは、自分でクォートを書かずに **プレースホルダー**（`$1`）を使います。クォートの扱いを含めて安全にしてくれます（→ 11 章）。

### 日付も文字列リテラルで書く

`'2025-10-01'` のように書くと、列の型（`DATE`）に合わせて日付として解釈されます。存在しない日付はエラーになります（実験で確認: `'2025-02-30'` → `ERROR:  date/time field value out of range: "2025-02-30"`）。型の詳細は `../PostgreSQL/03-data-types.md`。

### キーワードと識別子の大文字・小文字

- キーワードは大文字・小文字を区別しません（`select` でも `SELECT` でも同じ）。読みやすさのために **キーワードを大文字、名前を小文字** で書く慣習が多く、学習メモもこの書き方です。
- PostgreSQL では、クォートしない識別子は **小文字に変換** されます。`Transactions` と書いても `transactions` を指します。逆に `"Transactions"` とクォートして作ると大文字を含む名前になり、以後も毎回クォートが必要になるので、名前は最初から小文字＋スネークケース（`created_at` など）にしておくのが無難です。

### セミコロンと複数行

- 1 つの文は `;` で終わります。改行は自由に入れられます（学習メモの `CREATE TABLE` や `WHERE ... AND ...` の改行は見やすさのため）。
- psql では `;` を打つまで文が続いているとみなされ、プロンプトが `kakeibo_db=#` から `kakeibo_db-#` に変わります。`;` を忘れて Enter を押しても実行されないのはこのためです（→ `../PostgreSQL/02-psql-meta-commands.md`）。
- `\dt` のようなバックスラッシュで始まるものは SQL ではなく **psql のメタコマンド** で、`;` は不要です。

### コメント

```sql
-- 行末までコメント
SELECT item, amount FROM transactions; -- 文の後ろにも書ける

/* 複数行の
   コメント */
```

## 今後に活かせるポイント

- エラーメッセージの `LINE 1: ...` と `^` は、**解釈できなくなった位置** を指します。今回のように、原因はその少し手前（`''`）にあることが多いです。
- 「値はシングル、名前はダブル」とだけ覚えておけば、JavaScript との混同を防げます。
