# 並び替え `ORDER BY`

## 概要

`ORDER BY` は `SELECT` の結果の並び順を指定します。**`ORDER BY` を書かない場合、行の順番は保証されません**。「入れた順に返ってくる」ように見えても、それはたまたまです。

```sql
SELECT ... FROM ... WHERE ... ORDER BY 列 [ASC | DESC];
```

## このプロジェクトでの実装

### psql での練習

```sql
SELECT * FROM transactions ORDER BY amount ASC;
```

実験で確認した結果（`ASC` は省略しても同じ。既定が昇順）:

```text
 id |    item    | amount |    date
----+------------+--------+------------
  5 | 食料品     |  -3000 | 2025-09-20
  7 | 食料品     |  -2000 | 2025-10-10
  6 | カフェ     |   -600 | 2025-09-28
  4 | カフェ     |   -500 | 2025-10-05
  3 | おこづかい |  30000 | 2025-10-01
```

金額は符号付きなので、昇順だと「大きな支出」が先頭、収入が最後になります。

### backend での ORDER BY

`backend/src/index.ts:51`

```ts
historyQuery += ` ORDER BY date DESC`;
```

新しい日付が上に来るように **降順** にしています。`WHERE` の後ろに連結しているのは、SQL の文法上 `ORDER BY` は `WHERE` より後に書く決まりだからです。

## 重要語句

| 書き方 | 意味 |
| --- | --- |
| `ASC` | 昇順（小さい順・古い順・あいうえお順）。省略時の既定 |
| `DESC` | 降順（大きい順・新しい順） |
| `ORDER BY a DESC, b DESC` | まず a で並べ、a が同じ行どうしを b で並べる |

句を書く順番: `SELECT` → `FROM` → `WHERE` → `GROUP BY` → `ORDER BY` → `LIMIT`

## 仕様・注意点

### 同じ値どうしの順番は決まらない

`ORDER BY date DESC` だけだと、**同じ日付の行どうしの順番は保証されません**。実際の `kakeibo_db` には、同じ日付（2026-10-13）の行が 2 件（id 2 と id 3）入っています。今は毎回同じ順で返っているように見えても、データ量や実行計画が変わると入れ替わる可能性があります。

画面の一覧が再読み込みのたびに入れ替わる、ページネーションで行が重複・欠落する、といった不具合の原因になるので、**最後に一意な列（主キー）を足す** のが定石です。

```sql
SELECT * FROM transactions ORDER BY date DESC, id DESC;
```

実験で確認した結果:

```text
 id |    item    | amount |    date
----+------------+--------+------------
  7 | 食料品     |  -2000 | 2025-10-10
  4 | カフェ     |   -500 | 2025-10-05
  3 | おこづかい |  30000 | 2025-10-01
  6 | カフェ     |   -600 | 2025-09-28
  5 | 食料品     |  -3000 | 2025-09-20
```

### 文字列の並び順は照合順序（collation）による

文字列の `ORDER BY` は、データベースの照合順序の設定に従います。`kakeibo_db` は `\l` で見ると `Collate` が `en_US.utf8` でした。日本語の読み（あいうえお）順にはならない点に注意します。

### NULL の位置

PostgreSQL では、`ASC` のとき NULL は最後、`DESC` のとき NULL は最初に来ます（`NULLS FIRST` / `NULLS LAST` で変更可）。今のテーブルは全列 `NOT NULL` なので影響はありません。

## 今後に活かせるポイント

- 一覧を返す SQL には **必ず `ORDER BY` を書き、最後に主キーを入れる**。
- 並び順は API の仕様の一部です。OpenAPI の説明にも「日付の新しい順」などと書いておくと、フロント側が並び替えを前提にできます。

## 改善するなら

`backend/src/index.ts:51` を次のようにすると、同じ日の登録が「後から登録したものが上」に安定します。

```ts
historyQuery += ` ORDER BY date DESC, id DESC`;
```

（id は登録順に増えていくが、連番の保証まではない → `../PostgreSQL/04-identity-columns.md`。「登録順」を厳密に扱うなら `created_at` 列を持たせる。）
